# Branch location review and import

The CSV is staging/comparison material from the storefront directory: 42 locations in nine regions. Its Arabic names and addresses come from the storefront translation catalog. Company and fulfillment store codes are deliberately blank. No source records are installed or activated automatically. Structural validity does not establish current real-world accuracy.

1. Review authoritative branch data and retain each stable `directory_key`. Fill `company` with the exact allowed Odoo company name and `store_code` with the explicit `ab_store.code`. Names are never used to infer a store mapping. Duplicate store codes require correction before import.
2. Review English and Arabic names/addresses, region, latitude/longitude and source. Coordinates are mandatory; zero and geographic boundaries are valid. Preserve phones as text. Separate multiple verified public numbers with `;`. Keep the shared hotline in its own column. The staging file has no branch phone numbers.
3. Open **CRM → Import Branch Locations**, upload UTF-8 CSV, select **Validate CSV**, inspect all row errors, then **Import inactive profiles**. Validation rejects duplicates, ambiguous mappings, missing fields, invalid coordinates and conflicting existing mappings before applying any row. Changes to the CSV or existing profile revisions require validation again.
4. Open **Branch Locations**. Verify public phone numbers, set **Public Phones Verified**, document the review, then **Review and activate**. A profile with no public phone can be reviewed; its hotline remains separate. Content edits invalidate review and increment revision. Archive profiles rather than deleting them.

Each company/store has at most one profile, including archived profiles. Directory key, company and store mapping are fixed after creation. Update content on the existing profile; do not reuse a stable key for a different physical location. The directory does not edit synchronized store fields, CRM access branches, order routing or inventory.

Staff access uses the same employee session and conversation/company scope as Sales Chatter. The public directory lists every reviewed active location in that company whose mapped store is active, including stores unavailable for order fulfillment. Sharing public branch information does not grant permission to route orders or access inventory at that store. Existing assignments to another user/employee are rejected for non-managers. CRM and OMS form widgets prompt for the employee PIN if needed and preserve unsaved form edits. The OMS form requires a linked conversation. Channel-order dialogs preselect the current fulfillment store; otherwise the staff member selects a reviewed branch.

On 2026-11-08, the user selected the `e_commerce` storefront as the authoritative source for Callcenter and requested all 42 public locations in the picker. The reviewed Callcenter import is preserved in `docs/data/callcenter-branch-locations.csv` at the repository root. It records the company, explicit store codes, source revision and review provenance. Every Arabic branch name matched one active store exactly after removing only the store's branch prefix. The generic staging template remains unmapped for other installations. Do not import the Callcenter company mapping into another company without review.

**Send location** queues a native Telegram venue. **Send branch details** separately queues the previewed text with available verified phones and the labelled hotline. The composer and its attachments/reply remain untouched. Preview fallbacks are visible. Outgoing cards never offer customer delivery selection.

Enable only during an authorized rollout: upgrade Odoo consumers, deploy the gateway supporting venues, set gateway account `location_enabled=true`, then enable **Telegram Branch Locations Enabled** on the matching Odoo account. Existing account/global sending switches still apply. Defaults are disabled. Do not enable WhatsApp or send live test messages as part of source installation.
