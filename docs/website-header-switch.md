# Website header channel switching

The header treated each Website order as an independent account: a contact with two orders triggered the multi-account chooser and stayed on WhatsApp/Telegram after clicking the Website icon. Selecting an order did load the Website timeline, confirming the backend channel authorization and invoice membership were intact.

The Website adapter now marks its authorized navigation entries as sharing a timeline. The common header uses that explicit metadata to enter the Website timeline directly from another provider, restoring the last selected authorized Website order or opening the newest available order on first entry. Clicking Website while already viewing it keeps the order chooser available. Other providers retain their account chooser behavior.

Drafts and reply destinations remain tied to original conversation IDs. The initially loaded destination is remembered before leaving it, and superseded navigation responses still cannot replace a newer selection. No contact links, messages, orders, invoice snapshots, outgoing destinations or permissions are changed by this fix. No source UI labels changed, so existing English/Arabic translations remain applicable.
