# Website chat release and activation

> Historical record: versions, deployment state and validation results below describe the dated work only. Temporary QA scripts/evidence may have been removed. For the current order-status button and login-return behavior, use [the current guide](website-order-status-links.md). This record does not establish a current production rollout.

The release adds a v2 chat exchange alongside unchanged v1 confirmed-order intake. The Callcenter consumer is `ab_crm_website` 19.0.1.5.0; the source is `ab_storefront_callcenter_adapter` 19.0.1.1.1 with the operator-preserving `ab_ecommerce_storefront` 19.0.1.0.1 patch. Deploy the matching gateway `app/website.py` and `app/odoo.py` with the consumer before enabling source chat.

Order support uses native sale-order chatter. The compatibility URL reads that same history and retains signed-in ownership and guest checkout-session/capability checks. Submission is rejected until the initial order event is acknowledged. A later order revision does not close an acknowledged chat. New customer comments are captured transactionally; notes, employee/automated comments and bridge replies are excluded. No historical recovery is performed.

Floating support uses the website's native launcher and widget. A dedicated bridge operator keeps the configured channel available independently of employee presence. Its first customer input enters the durable queue, followed by an honest queued acknowledgement. Account/guest identities are scoped to the source; a signed-in account does not inherit a guest stream. Native session UUIDs remain distinct. Staff replies target the exact stored native session.

Callcenter keeps order and general support streams separate, including after contact linking. The latest incoming v2 customer message selects the default reply target; order revisions do not change it. A selector is shown for multiple eligible orders. The queued operation freezes its typed destination. Legacy operations without validated destination content move to review and are never dispatched. Messages remain text-only and bounded to 4096 characters.

## Monitoring and rollback

Monitor each endpoint/account separately. Source queues are `ab_storefront_callcenter_event` (orders) and `ab_storefront_callcenter_chat_event` (chat): count unacknowledged rows and compare the oldest `create_date` with current UTC. Destination chat receipts are `ab_crm_website_chat_event`; match `account_id`, event UUID and fingerprint. Gateway queues retain account, state, attempts and availability; outgoing operations retain their receipt, typed content, delivery state and error. Inspect pending/review counts and reply failures separately per account. Do not log credentials or message bodies.

Rollback chat by disabling source Chat Enabled/Outgoing Enabled, the affected Callcenter account's outgoing switch and its gateway sending switch. Keep endpoint/account order intake enabled. Preserve queues, messages, receipts, snapshots and reviewed destinations. Do not replay historical operations or rewrite UUIDs to recover a chat.
