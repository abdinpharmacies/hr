# Contact link/unlink lock contention — 2026-11-16

The failure was reproduced in live logs on notification/inbox refresh and manual unlink. Odoo's `lock_for_update()` uses `SKIP LOCKED` and raises `LockError`, a user error outside the request retry handler's concurrency exceptions. The automatic-link path previously acquired and wrote the branch before checking whether an existing identity was explicitly inactive. Repeated refresh therefore acquired unnecessary locks after unlink, while manual link/unlink exposed transient contention as a failed request.

The fix keeps authorization and scoped identity checks before mutation. Automatic matching now rejects inactive/conflicting identity associations before locking. Its mutation path is protected by a savepoint; a busy customer-association lock rolls back the attempt and leaves refresh available. Manual link/unlink converts only actual record-lock contention into a dedicated `ConcurrencyError` subclass, so Odoo retries the whole transaction with fresh state. Unlink now has an explicit savepoint for atomic rollback. Existing group previews, manager conflict review, company/branch restrictions and stale-fingerprint validation remain in force. Website candidate previews retain staff/session/branch/company validation and do not lock the messaging account.
