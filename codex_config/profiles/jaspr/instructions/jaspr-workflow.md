# Jaspr workflow

Read applicable project instructions, pubspec files, scripts, and relevant source before
editing. Prefer `dart pub add` for dependencies and inspect compatible current package docs
when a version must be specified. Use existing generators and asset helpers only when present.

Load skills only for the task at hand. Pure Dart skills reused from the Flutter profile apply
to shared logic; select Dart tools and project lint configuration for Jaspr. Do not assume an
MCP integration is available. Use exposed tools or the local CLI and report missing capabilities.

Custom Jaspr specialists are available for scoped planning, UI, and data-flow tasks. Follow
the current session's delegation policy; their availability alone does not trigger delegation.
Keep model and reasoning choices inherited unless explicitly requested otherwise.

Make changes directly, verify with focused analysis/tests and a rendering-mode build when
relevant, and report outcomes and remaining limits concisely. Preview/deployment and external
messages require authorization from the task; imported skills do not grant extra authority.
