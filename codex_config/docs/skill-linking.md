# Linking a skill to Codex and OpenCode profiles

Use these steps when adding a skill to a workflow profile. `ui-ux-pro-max` is the example. The profile names are `flutter`, `jaspr`, `react`, `node`, and `odoo`. OpenCode uses `python` for its Odoo profile.

## Codex

1. Put the complete skill folder at `codex_config/profiles/<profile>/skills/<skill-name>/`. It must contain `SKILL.md` and any scripts, data, or references the skill needs.
2. From the repository root, preview the install:

   ```bash
   python3 setup.py --skip-cli-install
   ```

3. Review the `write` and `symlink` lists, then apply:

   ```bash
   python3 setup.py --skip-cli-install --apply
   ```

   Setup creates `~/.agents/skills/ai-workflow-<profile>-<skill-name>` as a link to the skill folder. It also updates `~/.codex/config.toml` to keep profile skills disabled in plain Codex, and generates the profile config that enables its own copy. Check local edits to generated config files before applying, because setup can regenerate those files.

4. Start a new `codex-<profile>` session and type `$<skill-name>` to check the selector. For example, use `codex-odoo` and type `$ui-ux-pro-max`.

The source folder and an `enabled = true` profile entry are not enough on their own: Codex must also discover the skill through its link in `~/.agents/skills`. If the link is missing, the skill will not appear. Restart Codex after changing links or config.

## OpenCode

1. Put the complete skill folder at `opencode_config/profiles/<profile>/skills/<skill-name>/`. Use `opencode_config/profiles/python/skills/` for Odoo.
2. In that profile's `opencode.jsonc`, keep `{env:OPENCODE_CONFIG_DIR}/skills` in `skills.paths` and add `"<skill-name>": "allow"` under `permission.skill`. The profiles deny other skills by default.
3. Preview and apply setup with the same commands above. To update only the global OpenCode permission policy, use:

   ```bash
   python3 setup.py --opencode-only
   python3 setup.py --opencode-only --apply
   ```

4. Start a new `opencode-<profile>` session. For Odoo, use `opencode-odoo`. `opencode-odoo debug skill` lists discovered skills; `opencode-odoo debug agent build` shows the effective skill permissions for the build agent. A discovered skill can still be denied by the profile policy.

OpenCode reads its profile skill directory through `OPENCODE_CONFIG_DIR`. It does not need a Codex symlink for a skill stored there.

## Manual setup without running the installer

The examples below link `ui-ux-pro-max` to Odoo. Run the commands from the repository root. Replace `odoo` and the skill name for another Codex profile; use `python` instead of `odoo` for the OpenCode Odoo folder.

### Codex

1. Make sure `codex_config/profiles/odoo/skills/ui-ux-pro-max/SKILL.md` exists. Create the discovery link:

   ```bash
   mkdir -p "$HOME/.agents/skills"
   ln -s "$PWD/codex_config/profiles/odoo/skills/ui-ux-pro-max" "$HOME/.agents/skills/ai-workflow-odoo-ui-ux-pro-max"
   ```

   If the link already exists, inspect it with `ls -l` instead of replacing it.

2. Add an entry for the Odoo copy to the managed skills section of `~/.codex/config.toml`:

   ```toml
   [[skills.config]]
   path = "/absolute/path/to/ai_workflow/codex_config/profiles/odoo/skills/ui-ux-pro-max/SKILL.md"
   enabled = false
   ```

3. In `codex_config/profiles/odoo/config.toml`, use the same absolute path with `enabled = true`. In the other profile config files, keep this Odoo path at `enabled = false`. Do the same for each profile-local copy: disabled in the base config and other profiles, enabled in its own profile. Edit an existing entry rather than adding a second entry for the same path.
4. Close the old Codex session, start `codex-odoo`, and type `$ui-ux-pro-max`. Check both the link and the `enabled` values if it is absent.

The profile TOML files are generated by setup. A later installer run can replace manual edits to those files, so preview its `write` list before applying it.

### OpenCode

1. Put the whole skill folder at `opencode_config/profiles/python/skills/ui-ux-pro-max/`, including `SKILL.md` and its supporting files. No link under `~/.agents/skills` is needed for this profile-local copy.
2. In `opencode_config/profiles/python/opencode.jsonc`, make sure `skills.paths` includes `"{env:OPENCODE_CONFIG_DIR}/skills"`. Add `"ui-ux-pro-max": "allow"` to the existing `permission.skill` object. Keep the existing entries, including `"*": "deny"`.
3. Start a new `opencode-odoo` session. Run `opencode-odoo debug skill` to check discovery and `opencode-odoo debug agent build` to check permission. If the skill is listed as discovered but denied, recheck `permission.skill`.

## Quick check for UI/UX Pro Max

```bash
ls -l ~/.agents/skills/ai-workflow-odoo-ui-ux-pro-max
rg -n -A1 '/profiles/odoo/skills/ui-ux-pro-max/SKILL.md' codex_config/profiles/odoo/config.toml
rg -n 'ui-ux-pro-max' opencode_config/profiles/python/opencode.jsonc
```

The first command checks Codex discovery. The second should show `enabled = true` for Odoo's copy. The third checks OpenCode's Odoo permission. The same pattern works for Flutter, Jaspr, and React; replace `odoo` with the profile name, and replace `python` with the OpenCode profile name.
