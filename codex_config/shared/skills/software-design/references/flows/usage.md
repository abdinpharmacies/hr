# Usage flow

Use when the user asks how people use a feature, what happens after each action, or requests a user/actor journey. Identify distinct actors such as guest, signed-in customer, staff and API consumer only when relevant. Name the action at each stage, the visible result, and any handoff to another actor. Keep the main path easy to follow; add an alternate path only when it changes the user's understanding.

For an image, inspect the [accepted usage-flow example](../../assets/usage-flow-reference.png). Its reusable traits are clear entry paths, directional arrows, compact stage cards, and actor-specific actions within the stage. Adapt the layout and labels to the actual feature. Do not copy its eCommerce actors, sequence, technologies or data sources into unrelated systems.

Prefer a single visual reading direction for the main path. Route secondary paths around cards and labels. Label a shared step with each actor's relevant action when their behavior differs. Put implementation identifiers in small secondary text only when they help connect the user action to verified code.

Check the image at normal reading size for text collisions, arrow crossings and ambiguous handoffs. Preserve the accepted example as a usage-flow reference; the system-flow view remains a separate design task.
